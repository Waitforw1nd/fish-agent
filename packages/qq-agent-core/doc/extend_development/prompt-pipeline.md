# 提示词组装与请求流水线

一条入站消息从进入 `qq-agent-core` 到发出大模型请求，按固定顺序经过以下流水线（核心源码位于 `src/app.js`、`src/orchestrator.js`、`src/prompt.js`、`src/llm.js`）：

## 1. 入站过滤与唤醒判定

1. **白名单与免模型命令**：消息写入存档后先经过 `message.command` 插件（如 `.r` 骰子）；若插件返回 `{ handled: true }`，直接经 `SendQueue` 回复并结束，不唤醒大模型。
2. **档位唤醒（1～4 档）**：私聊默认全响应；群聊按档位检查 `@`、关键词或随机概率。未命中时直接标已读，**零 Token 消耗**；命中时根据触发类型决定携带的历史上下文条数（被 `@` 时携带最多上下文）。

## 2. 系统提示词（`buildSystemPrompt`）

人设优先级：**主人专属人设（若启用） > 分群独立人设（`personaByChat`） > 全局人设（`persona`）**（`botName` 与 `selfNickname` 始终保持账号级一致）。

拼接顺序（静态规则在前，最大化命中大模型前缀缓存）：
1. 机器人身份声明
2. **核心安全规则**与**工具调用协议**（固定最高优先级 `100+`）
3. 去 AI 腔调、主体性、群聊节奏、引用/点名、轻量记忆与表情包频率规则（随参与度与表情档位动态微调）
4. 多模态（看图）与联网搜索可用性说明
5. **已启用扩展的提示词片段**（`prompt.sections` 与动态 `promptSections(ctx)`，优先级强制上限 `99`，排在核心安全规则之后）
6. 用户附加规则（`customRules`）

> 若启用高级选项 `persona.systemPromptOverride`，仅替换中间的人格与聊天风格段落，【安全规则】与【工具工作方式】仍会强制保留。

## 3. 用户侧上下文消息（`buildUserPrompt`）

同样按“稳定在前、高频变化在后”排列以利用前缀缓存：
1. 【角色设定】与【可用表情包】
2. 【引导说明】
3. 【过去状态】（过滤撤回与屏蔽名单后的近期已读消息）
4. 【记忆】（仅提取本轮上下文实际出现的群友印象）
5. 【此刻状态】（群名、近期活跃度、距上次发言时间）
6. 【本次唤醒】（本轮触发消息批；若为冷场主动发言则追加主动话题提示）
7. 【当前时间】

## 4. 钩子加工、多轮工具循环与模型发送

1. **扩展钩子介入**：组装前触发 `before-context`，组装完 `messages` 数组后触发 `before-llm-messages`（允许原地增补上下文）。
2. **多轮 Function Calling**：文本工具结果写入 `tool` 消息；工具返回的图片/视频部件拆分为紧随其后的 `user` 多模态消息（兼容各类网关）。
3. **发送层适配（`src/llm.js`）**：按模态自动切换 `visionModel` / `videoModel`，调用 `llm.request-params` 插件适配推理/思考参数；若上游网关拒收图片格式则自动降级为纯文本说明重试。
4. **提示词在线预览**：控制台与云端 `/agent/prompt-preview` 均调用同一套 `buildSystemPrompt` + `getToolAvailability` 实时生成，所见即实际生效提示词。
