# 云端多入口：实现边界与设计核对

实现依据为 `C:/Users/Administrator/fish-agent-design.md`（2026-11-02 草案），同时遵守本次需求的更严格范围：B 站只有 L0 只读和 L1 待人工审核草稿，审核不发布，不执行 L2、不接真实支付、不部署。

## 实际结构

- QQ 协议与官方 QQ Bot 共用现有 `BotConnection` 的 QQ 槽位，互斥；桌宠与 B 站可以单独运行或与任一 QQ 入口组合。
- `tenant_entries` 记录显式启停。未配置此表的旧租户按已准备的 QQ/B 站配置兼容推导；入口启停、实例整体停启、驱动切换各自保留其语义。
- 同租户的入口变更、实例启停、QQ/B 站生命周期写接口共用串行队列，到期停止也进入该队列，避免较早的异步操作覆盖后来的状态。请求体按原限额读取后再排队，执行前重新验证登录及当前租户权限；只读接口和其他租户不等待此队列。每租户最多 64 个在途/待执行操作，超量返回 `429 LIFECYCLE_BUSY`；到期停止不被此上限拒绝。活动 QQ 驱动切换期间，入口变更返回 `409 QQ_SWITCH_ACTIVE`。该协调范围不包含普通配置写入，也不代表整个服务的所有异步任务都已串行化。
- 桌宠独立 Electron 包只持有设备令牌。云端 DesktopGateway 校验设备/租户，再代理到该租户 Headless 桌宠适配器。对话继续经过 ChatStore、Orchestrator、人设/记忆、SendQueue；桌宠身份无需配置 QQ 白名单。
- B 站桥接是独立进程。ExploreWatcher 使用只读发现/字幕上下文，经 loopback 鉴权请求同租户 Agent 生成日记/草稿；不启用工具调用或消息发送。单独运行桥接而未配置生成回调时，只保存只读上下文。
- BillingProvider 维护计量事件、套餐配额接口和查询；钱包 token 结算保持现有价格/预占/扣款流程。非 token 维度默认只记量，不新增计价或扣费。

## 与草案的差异及原因

| 项目 | 实际处理 | 原因 |
|---|---|---|
| 官方 OpenID 数字映射 | 保留 `qqbot_*` 字符串和 QQ 物理槽位；归因边界转为 qqbot/qq_official | Kimi 的本地实现、白名单和会话已采用字符串，强行转换会破坏现有数据。 |
| Relay attributionOf | 严格允许对应 group/private 的官方字符串；兼容旧 platform=qq 并归一化为 qqbot；其他平台按数字段验证 | 已核实旧函数会拒绝官方会话，问题通过本地 Relay HTTP 测试复现并覆盖。 |
| 数字号段 | B 站收窄为实际五块，桌宠占第六块；第七/八块保留 | B 站持久化映射从未分配到后续块；旧默认全段自动规范化，自定义冲突拒绝。 |
| 草稿通过 | 只记 approved 状态，不发送 | 本次用户明确禁止对外评论、限制为 L0/L1；没有发布按钮或发布通路。 |
| 桥接发现层 | feed 逻辑封装在 ExploreWatcher，复用已配置 UP 及关键词 | 避免无必要拆包；只读、低频、有限候选，不添加热门全站自动遍历。 |
| 主动等级表示 | API 使用 0/1，界面显示 L0/L1 | 现有 JSON 配置风格；更高等级在服务端拒绝。 |
| 设备席位 | 配对处始终执行配置的有限上限，其他配额默认 off | 席位是服务资源上限，按草案配对硬检查；不新增扣费。 |
| 旧官方记忆目录 | 新目录和成员文件采用全小写 Base32；旧下划线替换或 Base64 目录一律原样保留，不自动导入，即使有 `_meta.json.chatKey` | 旧目录可能已混入多个会话的成员文件，目录标记不足以逐项证明归属。需人工核查后迁移；独立消息归档仍仅在内部 chatKey 一致时兼容读取。 |
| 官方成员备注 | 官方 QQ 成员备注使用 `qqbot:` 加成员 OpenID 作为配置键；其他数字入口继续使用原数字键 | 旧裸键无法证明属于官方 OpenID，官方会话不会自动读取；如需使用，核实身份后在官方会话重新设置备注。 |
| 客户端分发 | 提供 Electron 独立包、锁文件、开发入口、NSIS/DMG 构建配置 | 本次不对外发布；真实安装包、macOS 与系统钥匙链验收需在对应平台完成。 |

## 启动与验证

沿用根目录 `npm start` 启动 cloud-manager。启用桌宠、生成配对码后，在客户端填写云服务地址和配对码。
仓库开发环境可执行 `npm --prefix packages/desktop-pet run dev` 复用已安装的核心 Electron；独立包通过 `npm ci`、`npm start` 运行。
反向代理使用公网 443 时设置 `CLOUD_PUBLIC_PORT=443`。服务端只接受设备专用路径，原面板鉴权和 CSRF 继续生效。

`npm run check` 检查包脚本，`npm test` 覆盖桥接、云端、面板、核心、Headless、多入口及桌宠客户端；`npm run test:all` 额外执行核心覆盖检查与 LLBot 类型/单元测试。
联调使用临时租户、本机假模型和协议端，不连接真实 QQ 或 B 站。桌宠真实 Agent/Relay 联调覆盖回复、按租户计量、回放和吊销；B 站联调覆盖只读内容、人设生成、token/浏览/草稿计量以及审核不发送。

v10 使用事务升级，并在取得 SQLite 写锁后重读版本，兼容多个启动进程的竞争；DDL 失败整体回滚，更新版本的数据库拒绝打开。`migration-v10.test.mjs` 使用冻结的 v9 SQL 和真实历史数据验证余额、账本、预占、充值、加密凭据与旧入口配置不变。旧 ledger 的 entry 保留 NULL；升级不会补扣、伪造历史入口事件或自动启用桌宠。

v2/v3 的自动发布、跨租户评论抢占、自动计价、真实支付、日汇总任务、皮肤、Live2D 和语音不在本次启用范围。
