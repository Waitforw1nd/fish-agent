# 桌宠 Gateway / Agent 交接记录

2026-11-03：此前 P1 交接表中的恢复元数据、回执查询、输入历史、请求关联和权限分类已在 Gateway、Headless Agent 与桌宠客户端落实。协议字段及兼容行为以 [desktop-protocol.md](desktop-protocol.md) 和当前实现为准。

## 已交接

- 客户端声明 `recovery.v1`、`receipt.v1`、`input-history.v1`；服务端返回能力交集。旧客户端不声明能力时仍可交互并接收逐帧 Bot 回放和在线 `msg.echo`，当前客户端也兼容旧服务端内嵌回放。
- 用户级 epoch、两套独立游标、最早保留序号、回放范围、缺口标志及结束帧已实现。Bot 回复和用户输入分别最多保留最近 200 条、24 小时；空回放区间的 from 为当前服务端序号加 1、to 为当前序号。客户端等待对应结束帧，按实际保存的帧推进游标；缺口明确提示，恢复不一致或存储失败时暂停自动发送。
- `msg.status` 支持 `accepted`、`in_progress` 和 `unknown`；同一用户最近 1000 个设备 ID + 客户端消息 ID 键用于去重和回执，按最旧淘汰，**没有时间保留保证**。`unknown` 不证明操作未执行。重试仍须使用原 ID，超出保留边界不承诺恰好一次。
- `INVALID_MESSAGE`、`INVALID_SEGMENTS`、`IN_PROGRESS`、`INGEST_FAILED` 等可关联错误携带请求 ID；正在处理的同一消息可向等待连接返回最终结果。ACK 只确认入站已接收并进入处理/调度，不代表模型已完成或已回复。结果不明确时客户端保留人工重试或放弃选择。
- 网关区分设备撤销、入口停用、用户失权和租户不可用的安全原因；4001 表示撤销，其他三项使用 4003。受控关闭码包括 1008，未知上游码归为 1011，不透传内部原因。

## 剩余边界与运维

- `qq-agent-core/src/app.js` 的 `desktop-processing` 标记保护存储和调度之间的不确定窗口。残留标记可能意味着副作用已经发生；先人工核查操作与历史，不得直接删除标记并重跑。即使有稳定消息 ID，也不能将回执缺失解释为未执行。
- 有限回放和去重不能保证长期离线后的完整历史或无限期幂等；跨设备输入与 Bot 回复各有独立窗口。客户端持久化失败时保留原游标和快照、暂停恢复，待存储修复后人工重连。
- 流式模型输出、TTS/ASR 和 emotion/turnId 属于后续产品能力。当前协议具备上述三项恢复能力，不应将它们列为尚未实现。
- 当前锁定的旧版 Electron 不满足打包安全基线；受网络限制尚不能下载受支持版本。当前执行环境的 Windows DPAPI 和 GPU/沙箱异常仍需在正常 Windows 用户会话验证；这些是客户端依赖或环境限制，不是后端协议缺陷。安全存储不可用时客户端拒绝明文回退。
