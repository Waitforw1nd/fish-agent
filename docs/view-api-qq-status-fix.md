# QQ 登录状态同步修复

日期：2026-10-30。

## 问题确认

人工账号测试发现：QQ 登录成功后，实例页面仍提示需要接入 QQ。

宁波服务器只读核查结果：NapCat 容器正在运行，`qq_runtimes.state` 和
`desired_state` 均为 `running`；QQ 账号状态为 `online`，实际账号与配置账号相符，
没有正在进行的内核切换。核查未输出账号、令牌或密钥。

已发现两个独立原因：

1. 实例摘要使用 Supervisor 的 QQ 子进程状态判断运行状态，但 NapCat 由 Docker
   托管；详情接口虽已取得真实 QQ 状态，却没有将结果交给摘要展示。
2. QQ 卡片的轮询只刷新卡片自身，父级实例接入检查项不会随登录结果更新。

## 实现

后端、前端与 Linux 验证分别由三个 GPT-6.1 Terra 子智能体负责；
主智能体负责跨层审查、记录及发布。

- 详情和启停响应复用已取得的真实 QQ 状态。列表、登录响应与管理员摘要也通过
  同一状态服务生成，不再用 Supervisor 的 QQ 子进程推断 Docker 容器。
- 列表复用最长 3 秒的已核验状态缓存，账号、运行资源、内核切换或进程状态变化
  时失效；批量列表限制并行探测数量。详情和 QQ 轮询仍进行真实探测。
- 保留账号一致性和 OneBot 运行代次校验，额外拒绝账号所记录的运行资源身份、
  代次与 Docker 资源不一致的情况。QQ 登录与 OneBot 连接分别展示。
- QQ 卡片首次读取或状态变化后通知实例页面；页面重新读取服务端就绪度，
  只更新顶部摘要，不重建表单或关闭扫码弹窗。状态不变时不重复读取摘要。
- 摘要读取失败或与轮询状态冲突时，下次轮询重试；旧请求、已离开页面的请求
  不覆盖新状态。在线按钮显示禁用的“QQ 已登录”，掉线后恢复扫码入口。

探测期间运行代次变化。
