# 管理员端上游与模型配置修改文档

## 1. 背景

当前平台公共上游、默认模型和可用模型目录分散在 systemd 环境变量、加密设置、租户数据库及静态代码中。此次服务器调整已验证新上游和模型可用，后续应将这些能力完整纳入管理员端，避免继续通过 SSH 修改配置。

本文记录本次临时调整、目标功能和验收标准。**文档不保存真实 API Key。**

## 4. 后续修改要求

### 4.1 保留自由 URL

- 管理员公共上游必须继续支持**自由填写完整 Base URL**，不得改成只能选择预置供应商。
- 保留实例级自定义上游 URL 能力，不得因增加公共上游管理而删除或锁定该入口。
- 不设置供应商白名单；支持任意 OpenAI 兼容端点，例如带或不带 `/v1` 的地址由现有 URL 拼接规则规范化。
- 仅保留必要安全校验：`http/https` 协议、禁止 URL 内嵌凭据，以及实例自定义渠道现有的 SSRF 防护。

### 4.2 上游 Key 与连接测试

- 管理员可保存、替换和清除 Key；留空保存时保留已有 Key。
- Key 继续加密存储，列表、日志、审计和错误信息不得返回明文。
- 管理页面增加“测试连接”和“刷新模型”，直接反馈 HTTP 状态、连接错误和拉取到的模型数量。
- URL 或 Key 变更后清理对应模型缓存，避免页面继续使用旧渠道结果。

### 4.3 默认模型管理

- 在管理员端增加平台默认模型设置，不再依赖手工修改 `CLOUD_DEFAULT_MODEL`。
- 默认模型应从当前上游实际拉取且可用的模型中选择，同时保留手动输入能力，以兼容不实现 `/models` 的上游。
- 保存时明确应用范围：
  - 仅用于新实例；
  - 同步更新仍使用平台旧默认值的现有实例；
  - 不覆盖实例自定义渠道或管理员单独指定过的模型。
- 对运行中的实例给出重启要求，并按现有 Agent 配置更新流程使其生效。

### 4.4 可用模型与定价管理

- 将模型启用状态、显示名称、上下文长度、最大输出和计费参数从单纯静态代码扩展为可持久化配置。
- 拉取到新模型后先标记为“未启用”或沿明确的管理员默认策略，不应因上游返回就自动向所有套餐开放。
- 管理员可决定各套餐可用模型，避免 Relay 的套餐白名单与上游列表不一致。
- 平台渠道新增模型必须具有明确计费参数；自定义渠道仍按现有规则不计平台费用。
- 上游不可用时可使用最后一次成功拉取的列表，并明确标记数据时间和降级状态。

5. 保留并回归验证自由 URL、实例自定义上游、密钥加密及 Relay 调用链路。

## 6. 验收标准

- 管理员可在页面填写任意合法 OpenAI 兼容 URL 和 Key，测试成功并拉取模型。
- 可将 `deepseek-flash` 或任一已启用模型设为平台默认模型，刷新页面后仍保持。
- 新实例和现有实例严格按所选应用范围更新，自定义渠道不受影响。
- 面板模型列表、套餐白名单、Relay `/v1/models` 和实际对话调用的结果一致。
- 更换 URL 或 Key 后刷新模型不读取旧缓存。
- API、页面、审计和日志均不泄露 Key；服务重启后配置仍有效。
- 覆盖管理员 API、面板交互、模型计费、实例默认模型更新及自由 URL 的自动化测试通过。
