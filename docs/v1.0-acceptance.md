# 养鱼 Bot v1.0 集成验收手册（Windows）

本手册针对当前源码工作区。验收服务使用真实 cloud-manager、租户 Headless、Desktop Gateway 和 Relay，本机假 OpenAI 模型生成固定测试回复；不连接真实 QQ、B 站或支付服务。脚本每次创建临时租户、数据库和随机管理员密码，仅监听 127.0.0.1，正常退出时删除本次服务目录。它复用仓库 `cloud-manager/test/helpers.mjs`、端口池及测试假入口，不能脱离仓库单独运行。

2026-11-03 集成收尾已补齐 Gateway/Agent 的恢复能力与客户端对接。本文保留此前 P1、交叉审查和集成收尾记录供追溯，**当前代码的全量结果、五条模拟链路证据及剩余限制，以末尾「第 18 轮独立全面 Review」为准**。历史记录的“4 项跳过”只统计 Node 测试运行器，遗漏旧自定义脚本中未执行却计为通过的分支。第 3、4、7、8 轮继续核查并修正测试报告和异常退出判断，第 14 轮补入此前遗漏的六个核心测试文件。下面的手动操作供 treez 在正常 Windows 登录会话验收。

## 准备和启动

在 Windows PowerShell 打开仓库。下面的 Node/npm 路径适用于当前机器；其他机器请换成已安装的对应路径。需要仓库已有 cloud-manager、qq-agent-core 和 desktop-pet 的运行依赖；开发模式在桌宠包未安装 Electron/ws 时可回退到 qq-agent-core 的开发依赖。不要向此环境填写真实账号或渠道密钥。

```powershell
Set-Location E:\bigPeach\fish
$env:Path = 'E:\harness\cursor\resources\app\resources\helpers;D:\tool\node;' + $env:Path
node --version
npm --version
node packages/desktop-pet/scripts/acceptance-cloud.mjs
```

保持窗口运行。脚本显示 `Panel`（含租户直达链接）、`Server URL`、`Temporary admin`、随机 `Temporary password`、`PID` 和临时目录。端口由系统或测试端口池分配。每次启动的地址、密码和租户都不同；不要把密码或配对码发给别人。脚本覆盖测试 helper 的默认域名，面板配对码中的 Host 与 `Server URL` 应一致，均为带实际端口的 `127.0.0.1`；若不一致请停止验收并排查。

另开 PowerShell 启动桌宠，并保持该窗口以便清理。下面为本次客户端创建独立目录，避免读取或覆盖已有的 `device.enc`：

```powershell
Set-Location E:\bigPeach\fish
$env:Path = 'E:\harness\cursor\resources\app\resources\helpers;D:\tool\node;' + $env:Path
$env:FISH_PET_DATA_DIR = Join-Path ([IO.Path]::GetTempPath()) ('fish-pet-acceptance-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $env:FISH_PET_DATA_DIR | Out-Null
Write-Host "本次客户端临时目录: $env:FISH_PET_DATA_DIR"
npm --prefix packages/desktop-pet run dev
```

## 配对和对话

1. 浏览器打开脚本输出的 `Panel`，用 `admin` 和当次随机密码登录。进入租户“通道托管”后，“接入方式”里的“桌宠”应为已启用；脚本已启动该租户实例。找到“桌宠设备”，点“生成配对码”。配对码有有效期且只能使用一次。
2. 在桌宠“服务地址”填本次 `Server URL`，“配对码”填面板显示的码，点“连接小鱼”。预期显示连接成功。凭据保存在上面指定的独立客户端目录；“清除本机配对”只清除本机凭据，不在云端撤销设备。
3. 输入中文并发送。预期看到输入及“本地验收模型回复：你好！”（后带调用序号），窗口中显示“AI 生成”。可连续发送多条，区分消息发送状态和模型回复。
4. 在服务窗口输入 `status` 查看连接数，输入 `disconnect` 主动断开当前桌宠连接。预期桌宠显示断线或重试，随后重新连接，再发消息收到回复。此命令只通过脚本标准输入操作，不开放控制 HTTP 端口。
5. 面板“桌宠设备”对应设备点“撤销”。预期连接终止并提示设备失效，不无限自动重连。需要继续时在桌宠点“清除本机配对”，在面板生成新码并重新配对。暂时断线时可按界面提示使用“重新连接”。

自动链路检查可在不打开桌宠窗口时执行：

```powershell
node packages/desktop-pet/scripts/acceptance-cloud.mjs --check
node --test packages/desktop-pet/test/acceptance-cloud.test.mjs
```

`CHECK PASS` 表示真实 `pairDevice/PetConnection` 已验证配对、消息确认和假模型回复、双设备同步、重连及撤销。新增 `RECOVERY PASS` 验证断线排队补发、离线用户输入回放，以及真正丢失 ACK 后重建客户端并查询持久回执，不重复调用模型；`METER PASS` 验证七条入站、七条出站、十四条模型账本、350 token 及设备在线时长/usage API。快照仅保存在内存，不等于 Electron 系统加密存储已经实机验收。

待确认状态的含义：`待发送` 表示已保存但尚未发出；`等待确认` 表示正在等待入口 ACK；`已受理` 表示服务端接受输入并进入处理/调度，不表示回复已完成。重连后先完成两路回放，再查询已尝试消息的回执：`accepted` 恢复为已受理，`in_progress` 等最终确认，`unknown` 保持结果未确认。处理或保存失败也按不确定结果呈现。仍不确定时自动队列暂停，由用户选择“重试（可能重复）”或“放弃”。Bot 回复和用户输入各保留最近 200 条/24 小时，去重键按用户保留最近 1000 个、无时间保证；不承诺长期完整历史或恰好一次发送。

内部窗口冒烟可用 `node packages/desktop-pet/scripts/smoke-electron.mjs`，会使用独立临时 profile、生成截图/报告并退出。`--compat` 仅用于受限测试环境的诊断，会对**测试进程**关闭 Chromium 沙箱和 GPU；不要把这些参数加入正常启动命令或正式包。该模式绝不绕过设备安全存储，也不用于真实账号。正常用户验收仍执行上面的 `npm --prefix packages/desktop-pet run dev`。

## 退出、清理和故障排查

桌宠托盘选“退出桌宠”，等待 Electron 完全退出；服务窗口在出现交互提示后输入 `quit` 或按 Ctrl+C，等待 `Temporary data removed`。服务和其临时租户随之消失，下次需要新码。客户端退出后，在启动桌宠的 PowerShell 窗口执行以下清理；只会删除该窗口记录的、本次创建的临时客户端目录：

```powershell
$petTempRoot = [IO.Path]::GetFullPath([IO.Path]::GetTempPath()).TrimEnd([IO.Path]::DirectorySeparatorChar)
$petTempDir = [IO.Path]::GetFullPath($env:FISH_PET_DATA_DIR).TrimEnd([IO.Path]::DirectorySeparatorChar)
if ([IO.Path]::GetDirectoryName($petTempDir) -eq $petTempRoot -and [IO.Path]::GetFileName($petTempDir) -match '^fish-pet-acceptance-[0-9a-f]{32}$') {
    Remove-Item -LiteralPath $petTempDir -Recurse -Force
    Remove-Item Env:FISH_PET_DATA_DIR
} else {
    throw '客户端临时目录不符合预期，拒绝删除。'
}
```

- 启动报缺模块：检查仓库相应包依赖是否安装，确认命令使用上面的 Node 和 npm；不要把生产 `.env`、数据目录或渠道配置复制进临时目录。
- 面板无法打开：核对输出的完整 `127.0.0.1` URL 和端口，确认服务窗口仍在运行；每次启动端口可能不同。
- 配对失败：检查租户已启动、桌宠入口已启用、服务地址来自本次输出；码过期或已用时重新生成。系统安全存储不可用时客户端会拒绝保存凭据。如果提示云端已兑换但本机保存失败，先在面板删除刚添加的设备，再修复系统存储并生成新码，原码不能重用。
- 没有回复：先看 `status` 是否有连接，再观察服务窗口错误；自动检查可区分链路问题与界面问题。不要改成真实模型地址来排错。
- 若服务窗口被强制关闭或机器断电，自动清理可能无法执行：先确认输出的 PID 及其子进程已停止，再人工检查输出的临时目录确属本次 `fish-cloud-test-*`，只删除该目录。不要删除其他测试或生产数据。若脚本报告停止未确认，会保留目录供排查。
